完整掌握 6 大檔案異常特徵與安全防禦原理

🟢 1. 沒有異常 (Clean File)

【正常檔案】符合標準副檔名規範，容量大小合理 (幾 KB ~ 數十 MB)，時間戳記符合當前時間，資訊熵較低，內文無混淆雜訊，屬於可信任的正常資料。

🔣 2. 亂碼與怪異字元 (Garbled / Corrupted Payload)

【混淆腳本】內文出現大量非文字符號 `?!@#$%^&*`，或檔名夾雜特殊字元。惡意程式常透過「代碼混淆 (Obfuscation)」掩蓋真實 API 呼叫，企圖繞過防毒特徵碼比對！

💥 3. 容量爆表 (Oversized Bomb / Decompression Bomb)

【解壓縮炸彈 / 零 Byte 毀損】標示容量出現極度誇張的數值 (如 888.8 TB、99.9 PB) 或 0 Byte 檔。駭客利用極高壓縮比演算法或垃圾字元填充 (Padding)，意圖在掃描時塞爆硬碟與記憶體造死機 (DoS)。

🎭 4. 偽裝雙副檔名 (Double Extension Camouflage)

【假圖檔真執行檔】檔名命名為 `summer_photo.jpg.exe` 或 `beach_resort.pdf.scr`。利用系統隱藏已知副檔名之特性，誘騙使用者誤以為是普通的圖片或 PDF 文件而點擊執行。

🔐 5. 高資訊熵 / 加密包 (High Entropy Payload)

【加殼勒索病毒】資訊熵 (Entropy) 衡量資料位元之混亂程度。高達 7.8 ~ 8.0 代表資料經過強烈加殼 (Packer) 或已被加密，常見於勒索軟體 (Ransomware) 或保護木馬。

⏳ 6. 時間軸錯亂 (Timestamp Anomaly)

【未來時間/極古老無效時間】修改時間出現在未來 (如 2099-12-31) 或無效年份 (如 1970)。這通常是木馬程式為了避開「近期修改檔案」安全審查所採用的「Timestomping (時間戳改寫)」偽裝戰術。
